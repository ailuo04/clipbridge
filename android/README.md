# 互传 Android 0.5.4

手机版提供会话、设备、传输、设置四个页面，支持系统深色主题与大字体。手机和 Windows 都只在用户主动点击、预览确认后发送剪贴板；不用 Shizuku、ADB 或默认输入法。

## 开发中的配对改进（尚未发布）

当前源码新增电脑显示二维码、手机主动扫码配对，以及网络变化后的快速搜索。二维码仅包含电脑的局域网地址和设备标识，不包含配对密钥；扫码后仍需两端核对并确认六位数字。相机仅在用户主动扫码时使用，拒绝相机权限不影响普通搜索和按 IP 配对。扫码不能绕过校园网或路由器的设备隔离。

Android 17 及以后即使应用目标版本仍为 36，也会检查本地网络权限；未授权时提供授权和系统设置入口，不会误报已经允许。现有已配对设备的信任记录保持兼容。上述改动尚未成为正式更新，请勿用调试包覆盖正式包。
## 安装与连接

首次从 GitHub 对应发行版安装正式 APK。已安装 0.4.0 正式版时直接覆盖安装，发布证书保持不变，原有配对保留。0.4.0 没有手机更新模块，因此这次需要手动升级一次。调试包使用不同证书，不能覆盖正式版。

电脑同时安装 0.5.4。两端接入同一 Wi-Fi 或手机热点并运行互传，手机打开后自动搜索；Windows 从托盘或控制面板打开“附近设备与配对”。附近指同一局域网，不包含蓝牙或跨互联网连接。路由器隔离、VPN 或 Windows 防火墙可能阻止发现。

点选附近设备发起配对，在手机设备页与电脑配对窗口核对同一组 6 位数字，分别确认一致。任意一端拒绝、数字不同或超时都不会建立信任。首次不用手填长密钥。以后同一网络内完成密钥认证后自动连接；每台设备分别保存配对材料，可在设置中单独取消。未验证的广播只显示为附近设备，不能直接发送内容。

旧版密钥入口在手机设置的“兼容旧版 / 手动连接”；旧配对仍可传输。旧版共享密钥无法提供新配对的逐设备隔离，撤销旧共享配对将影响使用该共享密钥的连接。

## 更新

手机打开时，距离上次成功检查满 6 小时会静默检查；可选的后台任务约每天检查一次，由系统决定实际执行时机。默认在非计费网络自动下载，也可手动下载。

更新使用既有 RSA 签名清单；GitHub Raw 连接失败时回退到同一仓库的 Contents API，并仍验证原始签名。下载检查 HTTPS 地址、包名、递增版本、长度、SHA-256、发布证书和当前安装证书。校验通过后只显示“安装更新”，用户点击才进入系统安装流程。系统要求允许此来源或确认安装时按系统提示操作。后台不启动安装器、不发横幅或声音、不打开应用界面。

## 发送和接收

手机设备页选择目标后发送文件或剪贴板。剪贴板内容只在点击时读取，预览后确认才发送。可从系统分享菜单把文件或文字交给互传，再主动选择目标发送。

接收文件在传输页主动接受或拒绝，约 100 秒未处理则超时。最多 256 个文件；不支持文件夹递归和断点续传。完整内容通过大小和 SHA-256 检查后保存到 Download/ClipBridge，同名文件保留原件。取消、失败和结束会清理该次临时文件。大文件需要足够缓存空间。

传输页展示本次连接服务内的请求、文件摘要、进度和结果；不保存剪贴板历史正文。收到的文字会尝试写入剪贴板，也提供“复制最近收到的文字”作为系统限制时的前台入口。文字“已发送”不宣称目标已成功粘贴。

## 安卓版本兼容

最低 Android 10（API 29），当前 compileSdk / targetSdk 为 36。使用公开系统接口、系统文件选择器、MediaStore 和系统安装流程，不依赖厂商私有接口。按系统主题适配明暗界面；系统边距和大字体保持可滚动。

Android 17 / API 37 起，当前开发版会检查 ACCESS_LOCAL_NETWORK 的实际授权状态，即使应用目标版本仍为 36；Android 16 及更早系统不会请求不存在的权限。若系统不再显示授权弹窗，可在应用的系统权限设置中手动允许。提升目标版本时仍需同步升级 SDK / 构建工具，并验证本地网络权限、连接前台服务、后台任务和安装规则。

系统可能延后后台更新或限制剪贴板写入。界面提供手动检查更新、前台复制接收文字、重启搜索和停止连接入口。没有开机强制打开页面或后台拉起 Activity。

## 构建与验证

JDK 17、SDK 36、Build Tools 36.0.0；Gradle 8.14.6、AGP 8.10.1、Kotlin 2.1.20。

~~~powershell
./gradlew.bat testDebugUnitTest lintDebug assembleDebug --no-daemon --max-workers 2 --console plain
dotnet run --project ../tools/TransferTests -c Release
~~~

在 ASCII 临时目录启动 C# 测试服务器，再设置环境变量运行 JVM 单元测试，可验证实际互通：

- `TransferTests --interop <目录>` 对应 `CLIPBRIDGE_INTEROP_DIR`：旧版文件协议双向互通。
- `TransferTests --experience-interop <目录>` 对应 `CLIPBRIDGE_EXPERIENCE_INTEROP_DIR`：真实 C# 配对服务、承诺 / ECDH / 短验证码，以及逐设备文字和文件通道的双向互通。测试仅使用回环网络、合成设备和测试内容，不使用真实剪贴板或真实配对密钥。

正式签名仍由既有 GitHub Actions Secret 和 tools/Build-AndroidRelease.ps1 完成；不得换用调试证书发布。发布同时包含 Windows Setup、ZIP 与 Android APK，所有资产匿名下载验证成功后再更新签名清单。

一加 15 / ColorOS 真机、真实 Wi-Fi 与热点、Windows 防火墙、系统安装确认及 1 GiB 真实手机传输需要实机验证。开发期间只做无界面检查，不运行 UI smoke test、模拟器、安装器或应用窗口。

## 界面与无界面回归

手机端以“会话”为首页，并保留“设备 / 传输 / 设置”三个入口，统一柔光玻璃卡片、圆角操作和底部导航。设备页优先展示当前目标与主动发送；传输页区分待接收、进行中、已完成和未完成；设置页将 IP 和旧版共享密钥入口折叠到高级连接。浅深色与跟随系统继续使用既有偏好。

应用内确认使用统一底部弹窗，长内容可滚动，输入时请求窗口调整大小。文件选择、权限请求、相机扫描和 APK 安装仍交给系统及原有组件；安装前仍完整验证更新包。

新增 UiPresentationTest 覆盖实际计数进度、大文件溢出、传输分组、准备文件计数单位、小屏/大字体操作排列、更新状态及滚动恢复。仓库根目录可运行 `python tools/test_android_ui_style.py`，静态检查主按钮渐变两端与正文的颜色对比，不启动 Android。

使用 JDK 17 运行 Gradle；不要因本机 Android Studio 自带运行时较新而改动工程依赖。Windows 中文路径若导致 Gradle 测试执行器无法加载类，应从指向同一工作区的 ASCII 目录别名运行构建。Debug APK 仅用于开发验证，不是正式发布包，不应覆盖不同证书的已安装正式版。
