# 互传 Android 本地测试版

这个安卓客户端与 Windows 手动互传预览版配合使用。两端都只有在用户主动点击发送后才读取、发送剪贴板纯文本；不依赖 Shizuku、ADB 或输入法权限。

## 安装和配对

1. 在手机安装本地生成的 APK。它使用 Android 开发测试签名，适合此次本机试用；尚未作为正式 Android Release 发布。
2. Windows 运行配套的手动互传预览版。默认只显示托盘图标，点击托盘中的“打开控制面板”。如已有旧版 ClipBridge 正在运行，请先从旧版托盘退出，再启动预览版。
3. 两端接入同一 Wi-Fi 或电脑连接手机热点。
4. 将 Windows 显示的 64 位配对密钥输入手机，点击“保存配对”。请通过你信任的方式输入密钥，不要把真实密钥提交到问题报告或日志。
5. 手机点击“开始连接”。系统会显示连接服务通知，可以在通知中停止。若自动发现失败，在手机输入 Windows 面板显示的局域网 IPv4 地址。
6. Windows 首次联网可能需要你允许系统防火墙的专用网络访问；此次开发不会主动更改你的防火墙。

## 文字与文件

- 手机复制文字后打开互传，选择设备，点击“发送剪贴板”，检查预览后确认发送。
- Windows 从控制面板或托盘选择“发送当前剪贴板”，预览后选择目标发送。成功写入网络的文字显示“已发送”，不宣称对端已经完成写入。
- 手机在接收后尝试写入剪贴板，也保留“复制最近收到的文字”作为系统限制时的前台恢复入口。文字不自动回传。
- 选择普通文件或从系统分享菜单选择互传。首版支持一次 1 至 256 个文件，不支持文件夹递归。
- 接收文件需要在目标应用的请求列表中点击接受，约 100 秒未处理则拒绝；后台收到请求不会打开窗口、切换前台或播放提示音。
- Windows 默认保存到用户 Downloads/ClipBridge，手机保存到 Download/ClipBridge。文件完整接收并通过 SHA-256 检查后才发布到接收目录，同名文件保留原件。
- 手机发送文件会先在缓存中准备稳定副本并计算哈希，接收也会先使用临时文件。大文件需要足够的缓存和下载目录空间；取消、失败或正常结束会清理该次操作的临时副本。
- 传输失败后可以手动重试。首版不支持断点续传。

## 游戏期间安静运行

Windows 启动不打开控制面板，接收请求只进入列表，自动更新检查只记录状态。此版本没有接收弹窗、托盘气泡、窗口闪烁或自动聚焦；只有用户主动点击相关菜单时才打开界面。开发验证同样不启动应用、模拟器或交互测试。

## 本地构建

需要 JDK 17、Android SDK 36、Build Tools 36.0.0；Gradle wrapper 固定 8.11.1，AGP 固定 8.10.1，Kotlin 固定 2.1.20。在 android/local.properties 写入本机 sdk.dir（该文件不提交），然后运行：

~~~powershell
./gradlew.bat testDebugUnitTest lintDebug assembleDebug --max-workers 2 --console plain
~~~

APK：app/build/outputs/apk/debug/app-debug.apk。Windows 无界面测试：

~~~powershell
dotnet run --project ../tools/TransferTests -c Release
~~~

JVM/C# 双向文件协议测试：先运行 TransferTests 的 --interop <临时目录> 模式，再将 CLIPBRIDGE_INTEROP_DIR 指向同一目录并运行 JVM InteropTest。测试仅使用回环端口、测试密钥和合成内容，不读写真实系统剪贴板，也不启动 UI。

## 验证边界

自动化测试和构建不等同于一加 15 实机验证。手机系统剪贴板、系统文件选择器、MediaStore 保存、ColorOS 后台限制、真实 Wi-Fi/热点、防火墙以及 1 GiB 视频的实际手机传输，需要在你方便使用手机时逐项验证。Windows 交互式 UI smoke test 仅编译，按用户游戏期间不打扰的要求不执行。
