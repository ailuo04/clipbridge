# ClipBridge 双端轻量收发与历史时间线 UI 重构设计

日期：2026-11-06  
状态：设计方向已在对话中逐节确认；待用户审阅本文件。

## 1. 目标

全面重做 ClipBridge Windows 与 Android 的界面，使配对后的日常使用变成轻松、简洁、清晰的收发体验。核心工作区采用按设备区分的对话时间线，混合展示该设备之间已发送和已接收的文字、文件及传输状态。

两端共用同一套产品概念、历史记录语义与视觉语言，但各自保留平台原生交互：Windows 使用连接后的紧凑小窗口；Android 使用应用内时间线主界面，不使用覆盖其他应用的系统悬浮窗。

## 2. 非目标与保持不变的边界

- 不迁移 Windows WinForms 和 Android 原生 Kotlin UI 技术栈；重做整个呈现层、导航和页面，而不是重写网络栈。
- 继续复用现有设备发现、配对信任、文件/文字传输、接收确认、安全校验、剪贴板显式操作和更新能力。
- 不引入云端历史服务。历史内容只在已配对设备之间经现有可信连接同步。
- 不改变 RSA 签名清单、下载校验、安装器权限、更新公钥或 GitHub 发布约束。
- 历史同步只扩展新版本间的能力；不支持该能力的旧版本仍可照常配对和收发，但不能共享新历史时间线。

## 3. 页面与导航

### Windows

- 未完成配对时显示重新设计的配对/设备发现与设备管理界面。
- 连接成功后自动进入紧凑时间线窗口。窗口标题区域显示当前设备及连接状态；主体显示时间线和文本/附件发送区。
- 当前窗口提供设备切换、打开设备管理、设置和本地接收文件位置等入口。每台已配对设备有独立时间线。
- 点击小窗口的关闭按钮时隐藏到系统托盘并保持连接；用户可从托盘重新打开窗口。只有明确选择托盘中的“退出应用”才结束应用和连接。隐藏/退出均不删除历史。

### Android

- 应用内时间线作为主要工作界面；顶部选择当前设备，切换设备即切换对应时间线。
- 配对、设备管理、设置、更新和本地接收文件位置从清晰但次级的入口进入。
- 不申请系统级覆盖浮窗权限来模拟桌面小窗。

### 所有页面

重新设计配对/二维码、设备管理、连接后时间线、收件确认、设置、更新状态与确认弹窗。信息层级统一，但页面布局遵循桌面与触屏差异。

## 4. 时间线与跨应用操作

- 时间线按原始事件时间排序；每条事件标明发送/接收方向、设备、类型、时间和结果。
- 文字项提供复制操作；文件项提供打开及拖动/复制等适用操作。
- Windows 支持将收到的文件拖入其他应用，或复制后在目标应用粘贴；文字支持复制、粘贴和适用场景下拖动。窗口也接受文件拖入以发起发送。
- Android 使用系统复制、分享和内容 URI 等原生交互；目标应用及系统支持时提供拖拽，不承诺所有应用都支持跨应用拖放。
- 发送文字或文件始终是用户主动操作；粘贴到发送区不等于自动发送。接收文件保留现有显式接受/拒绝流程。
- 两端均提供独立的“本地接收文件 / 打开保存位置”入口，打开系统文件管理器或对应保存位置。历史记录删除不删除本地文件；从系统文件管理器删除文件仅影响当前设备。

## 5. 历史数据与同步

### 记录内容

持久保存时间线需要的事件元数据和文字正文。建议记录至少包含：稳定事件 ID、事件创建时间（UTC）、会话/配对设备 ID、发送方设备 ID、内容类型、文字正文或文件元数据、传输状态及必要的版本信息。接收文件的二进制内容继续保存在应用现有的本地接收目录，不放进历史数据库；文件路径是本地信息，不随历史同步发送。

### 同步

- 通过已配对双方现有的认证/可信通信链路传输带版本号的历史事件，不经过第三方服务器。
- 每个配对设备各自形成会话；事件只同步到该会话对应的配对端，不把一台设备的历史广播给其他配对设备。
- 设备离线时先本地保存；重新连接后交换缺失事件。同步须幂等并按稳定 ID 去重，支持断线重试。
- 文字正文随对应会话的历史同步；文件只同步历史元数据，不因补齐历史而再次传输文件字节。
- 历史同步错误应独立于收发业务；同步失败不应阻止正常文字或文件传输，并在后续连接时重试。

### 保留与删除

- 历史记录自原始发送/接收时间起保留 7 天；同步不会重置计时。
- 自动过期只清除两端对应的历史记录，不删除已保存的本地文件。
- 用户手动删除时间线记录时，删除标记同步到该会话的配对端，防止离线副本之后重新出现；记录删除绝不删除本机或远端文件。
- 删除本地实际文件只通过独立文件位置入口在本机文件管理器中完成，不由时间线删除操作触发。
- 首次启用该功能后开始建立新历史；不能从旧版仅临时显示的传输行中伪造或推断历史正文。

## 6. 视觉与可访问性

选择“轻雾玻璃”方向：淡蓝紫渐层、柔光与半透明表面、圆润控件和安静的层级。玻璃、模糊和装饰效果从属于内容可读性，不用于承载低对比度文字或关键状态。

保留浅色、深色与跟随系统主题。使用明确的在线/离线、进行中、完成、失败和待处理状态；颜色之外同时使用文字或图标表达。Android 控件需适配大字体和至少 48dp 的可触区域；Windows 保留键盘导航、合理焦点顺序和可缩放布局。动效轻量，不延迟关键操作。

## 7. 错误与边界情况

- 断线时显示离线状态，保留本地时间线；再次连接后恢复同步。
- 重复、乱序或重试到达的记录由稳定 ID 与版本规则去重，不产生重复气泡。
- 手动删除产生的同步墓碑在配对端确认前保留在内部状态，但不显示为用户消息。
- 过期记录即使由离线设备重新送达，也因原始时间超过 7 天而不重新显示。
- 文件传输失败与历史同步失败分别呈现；文件存储空间不足、保存目录不可用或本地历史写入失败时，给出可恢复的清晰提示，不虚报成功。
- 旧版本不认识历史同步能力时跳过该能力协商，原有配对及文件/文字协议行为保持兼容。

## 8. 验证方案

### 历史与协议

- 覆盖 7 天边界、时钟/时区统一使用 UTC、自动过期不删文件、手动删除同步、墓碑离线保留、重连补齐、重复/乱序事件去重。
- 覆盖同一配对会话隔离、多个配对设备间不串历史、文件元数据同步但不重复传输文件字节，以及新旧版本能力协商。
- 模拟网络中断、存储错误和同步重试，确认正常收发与历史同步错误隔离。

### UI 与平台操作

- Windows 验证连接后紧凑窗口、设备切换、设备管理入口、文本复制/粘贴/拖动、文件拖放/复制、保存位置打开和从文件管理器删除。
- Android 验证主要时间线、设备切换、系统分享/复制、保存位置打开及大字体/窄屏布局。
- 两端均验证浅色/深色、长文本、长文件名、空历史、离线、待接收、进行中、成功和失败状态。
- 对真实第三方应用的拖放/粘贴支持按平台和目标应用分别验收；不以单一目标应用成功推断所有应用兼容。

### 回归边界

运行适用的 Windows 与 Android 构建、历史/协议测试和 UI 回归测试；确认原有配对信任、文件完整性检查、更新签名验证、安装器权限及正式发布流程未被破坏。构建通过不替代真实设备、真实网络或跨应用操作验证，未执行的项目应明确标记为未验证。
