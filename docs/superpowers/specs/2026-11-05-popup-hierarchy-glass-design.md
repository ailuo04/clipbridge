# ClipBridge 弹窗层级与雾透胶囊视觉设计

## 目标

为 ClipBridge Windows 端自有的短时提示、确认和更新弹窗建立一致且容易扫描的视觉层级。整体采用用户选择的“状态先行”结构，并将成功状态区做成 A 方向的雾面液态玻璃胶囊；同一组件按成功、警告、错误和进行中状态切换语义色。改造只影响视觉表达和消息组织，不改变更新、配对、文件传输或安全校验行为。

## 现状与问题

- 更新结果、更新错误和更新进度通过 `UpdateDialog` 展示；最新版本提示复用更新窗口并压缩布局。
- 启动异常仍使用系统 `MessageBox`，外观与 ClipBridge 窗口分离。
- 待配对请求实际呈现在 `DevicesForm` 的卡片中，而不是独立模态框；当前卡片同时呈现设备、验证码、有效期和确认/拒绝动作，层级需要与新弹窗体系一致。
- 文件选择使用 Windows 原生 `OpenFileDialog`，继续保持系统原生外观。

## 范围

### 包含

1. 更新弹窗：可用更新确认、下载与校验进度、安装等待、完成、失败与重试，以及“已是最新版本”和检查失败短提示。
2. 启动失败提示：由 ClipBridge 自绘、主题一致的错误提示替代原生 `MessageBox`；继续显示当前可安全展示的错误类别和解决建议。
3. 设备配对待确认卡片：强化设备身份、验证码、有效期和确认/拒绝按钮之间的主次关系，并使用相同语义状态胶囊。
4. 如果弹窗改造过程中发现同一 Windows UI 路径上的 ClipBridge 自绘短时错误或确认提示，使用同一层级与语义色规则；不扩展到 Android UI。

### 不包含

- Windows 原生文件选择框。
- 设备列表、传输记录、手动发送等完整独立窗口的整体重设计。
- 任意网络、更新协议、签名、公钥、哈希、安装权限或发布流程更改。
- 将主窗口状态栏或所有普通信息卡强制改成玻璃材质。

## 设计原则

### 1. 状态先行，单一主结论

信息阅读顺序固定为：状态胶囊（状态类型、简短上下文与唯一主结论）→必要说明或详情→主要动作。成功提示不重复两遍“已是最新版本”；如果胶囊已完整表达结论，详情区只展示有额外价值的版本、检查时间等信息，无法补充新信息时直接省略。进度提示让当前阶段和进度成为主信息；错误提示先说明当前影响，再显示原因与下一步。

### 2. 采用 A 版雾面玻璃胶囊

- 状态区采用横向、两端全圆的胶囊轮廓，置于弹窗内容顶部，内部排列状态图标、状态上下文、主结论及可选版本/安全短标签。
- 使用低饱和薄荷/冰蓝渐变、柔和漫射高光、极细亮边和轻微内外阴影，表现雾透玻璃；不使用强烈炫光、厚重描边或大面积彩色发光。
- 仅状态胶囊采用明显玻璃表现。正文详情区域保持较稳定、低干扰的表面，按钮保持明确的实色主次。
- 文字与图标不降低不透明度；透明效果仅用于胶囊背景、描边和高光。WinForms 实现使用本地绘制的玻璃质感，不进行屏幕抓取或依赖动态桌面模糊。
- 浅色与深色主题均需保证文字、图标和细边界可辨；遵循现有 `Ui` 主题角色与高 DPI 缩放。

### 3. 按状态使用语义色

- 成功/最新：柔和薄荷绿，主按钮使用现有蓝色强调色。
- 待确认/注意：柔和暖黄；确认与拒绝动作清楚分开。
- 可恢复错误：柔和红色状态胶囊；可恢复时重试为主要动作，关闭为次要动作。
- 更新进行中：蓝色状态胶囊；阶段、真实进度、速度/剩余时间仍按既有更新逻辑展示。
- 危险动作使用明确危险色，并保留原有防误触语义。

### 4. 操作和内容层级

- 一个弹窗最多一个视觉主操作；关闭、稍后处理、取消等动作保持次级，但下载/安装过程中已有的取消限制必须保留。
- 配对请求中设备名和验证码具有足够突出度，地址与有效期为次级信息；过期请求仍禁用确认和拒绝动作，既有行为不变。
- 错误细节保留可读性，但不以装饰性色块或超大标题压过下一步操作。
- 保留关闭按钮、键盘焦点、可访问名称、进度可访问对象及现有拖动/关闭行为。

## 实现边界建议

- 新增一个可复用的自绘状态胶囊控件或等价的小型绘制组件，负责成功/警告/错误/进行中四种主题化状态，并以 DPI 缩放所有尺寸。
- `UpdateDialog` 使用该组件统一短提示、进度和错误状态；保留下载、校验、取消、安装保护、重试和新版本启动确认的既有状态机。
- `DevicesForm.AddRequest` 在既有配对卡片中复用状态胶囊的图标/材质与层级规则，不把待配对卡片改成新的模态弹窗。
- 启动异常提示复用主题一致的 ClipBridge 自绘短提示，而不是继续显示原生 `MessageBox`；不要将异常对象、密钥或更新载荷写入新界面。
- 文件路径、业务协议、用户数据、更新发布资产和版本号均不变。

## 验收标准

1. 最新版本、检查失败、可用更新、下载/安装进度、更新失败和启动失败均呈现相同的状态优先结构，状态类别可一眼区分；结论不重复显示，详情仅在提供额外信息时出现。
2. 胶囊轮廓确实为两端全圆，材质表现接近 A 版：雾透、柔和、有细高光但不过度反光；正文与操作仍清晰。
3. 配对请求的设备身份、验证码、有效期与确认/拒绝操作有明确主次；过期和已处理状态符合现有行为。
4. 浅色、深色和放大 DPI 下没有裁切、重叠或对比度问题；文字保持不透明且可访问性名称、键盘操作可用。
5. 更新签名/哈希/大小/HTTPS 校验、取消边界、安装保护、发布入口和配对/文件传输协议均无行为变化。

## 验证策略

- 扩展 UI smoke test，覆盖 `UpdateDialog` 的成功、可用、进度、错误和安装保护状态，以及状态胶囊在浅色/深色主题和缩放后的布局、可访问性与文本尺寸。
- 扩展设备窗口 smoke test，覆盖配对请求卡片、错误/过期语义、验证码呈现和确认/拒绝动作仍可用。
- 验证启动失败路径使用 ClipBridge 自绘提示，并且系统文件选择框仍保持原生。
- 运行 `dotnet build` 与 UI smoke tests；按仓库 UI 变更约定执行必要的更新/发布 smoke checks，确认发布协议文件未被改动。
