# ClipBridge 清透液态玻璃与统一品牌图标设计

## 目标

把 ClipBridge 的 Windows 与 Android 主要界面统一到“清透浅色玻璃”视觉语言，并把更新流程的所有状态统一到同一套组件和动效规则中。电脑和手机使用同一个品牌符号：保留现有文件夹与双向传输箭头的识别度，采用“同标升级”方向，让 Windows 图标与 Android 自适应图标在不同平台上保持一致但符合各自的图标容器规范。

本次工作只调整视觉、布局和图标资产，不改变剪贴板传输、设备发现、配对、自动更新、安全校验、签名验证或发布协议。

## 范围

### Windows

1. 更新窗口的确认、下载、校验、解压、等待退出、安装、重启、完成、失败和重试状态全部使用清透浅色玻璃视觉。
2. 主设备窗口、设备状态卡片、配对二维码窗口、配对提示和错误/结果提示逐步使用同一套玻璃表面、按钮、徽标、图标和状态色。
3. 保留无边框圆角窗口、标题栏拖动、Alt+F4/Escape、键盘可访问性、长文本滚动、安装期间禁止误关闭等现有行为。

### Android

1. 主页面、设备列表、传输状态、配对流程、更新提示和主要对话框使用与 Windows 相同的颜色层级、玻璃卡片、圆角按钮和状态色。
2. 保留 Android 的自适应布局、触摸反馈、深色模式、系统返回行为、辅助功能和小屏/大字体布局。
3. 更新 Launcher 图标：使用与 Windows 相同的文件夹与双向箭头核心图形；Android 端采用自适应图标前景/背景和安全边距，避免在不同启动器的遮罩下被裁切。

### 不在范围内

- 不修改版本号、发布清单、更新 URL、RSA 公钥/私钥、SHA-256 校验或 GitHub 发布流程。
- 不承诺 Authenticode 代码签名、真实安装目录升级、真实 GitHub 网络升级或多显示器物理 DPI 切换验证。
- 不把所有控件都做成透明；文本和关键操作优先保证清晰度与可操作性。

## 视觉系统

### 设计关键词

清透、轻薄、柔和蓝紫光、白色高光、可读、克制。玻璃效果使用本地绘制的渐变、半透明填充、边缘高光、柔和阴影和局部辉光，不截取桌面背景，也不依赖系统模糊 API。

### 颜色与层级

- 画布：浅蓝白渐变，叠加低对比度蓝紫/青色辉光。
- 主表面：半透明白色或极浅蓝白，使用一层细白边和一层低对比内边。
- 次表面：比主表面更低的透明度，用于更新说明、进度和次要信息。
- 文字：深蓝黑色主文字、低饱和蓝灰次文字；错误使用高对比酒红，成功使用深青绿。
- 强调色：蓝紫到明亮蓝的渐变，应用于主按钮、进度填充、选中态和品牌辉光。
- 深色模式：保留同一色相关系，降低表面亮度与辉光强度，不能把白色文字放到对比不足的渐变上。

### 组件规则

- 玻璃表面：18–24dp/px 圆角，细边框，内部上缘高光，内容区域保持不透明或高对比。
- 主按钮：胶囊形、蓝紫渐变、明确的悬停/按下/禁用态；次按钮为透明玻璃表面。
- 状态徽标：使用图标加短文本，颜色只表达状态，不承载唯一信息。
- 进度：显示总体百分比和真实字节/阶段信息；动效可关闭时仍保持静态可读。
- 图标：线条圆角、几何比例一致，避免在小尺寸中堆叠过多装饰。

## 品牌图标设计

以现有电脑图标的“文件夹 + 双向传输箭头”为核心，不直接把桌面 `.ico` 位图缩放到 Android。先定义一份可复用的矢量几何：文件夹轮廓、前后层次、双向箭头、圆角端点和清透高光。

- Windows：输出包含多尺寸和透明边缘的 `.ico`，同时用于可执行文件、窗口标题栏和更新徽章的品牌参考。
- Android：输出矢量前景与背景资源，使用自适应图标声明；前景保留安全边距，背景使用清透蓝紫玻璃层，保证不同启动器遮罩下仍与 Windows 识别一致。
- 图标更新必须有浅色、深色/高对比和小尺寸检查；不能因为玻璃高光导致箭头方向或文件夹轮廓消失。

## 组件与数据流

### 共享视觉边界

Windows 继续使用 `Ui`、`VisualDrawing` 和更新窗口的本地绘制控件作为视觉基础；Android 继续使用 `BridgeUi`、`GlassDrawable` 和现有主题 token。两端不共享运行时代码，但共享一份明确的设计 token 和品牌几何约定，避免单独调色导致品牌漂移。

### 更新流程

更新协议和 `UpdateProgress` 数据保持不变。`UpdateDialog` 只负责把阶段、百分比、字节数、速度、剩余时间、说明和失败原因呈现为统一的玻璃状态：

`发现新版本 → 下载 → 校验 → 解压 → 安装 → 重启 → 完成`

取消、重试、安装期间关闭保护和独立安装助手的生命周期不变。任何网络、签名、大小、哈希或解压失败都显示可读原因，并保留当前版本可用的事实。

### 设备与配对流程

设备发现、连接、传输、二维码和邀请逻辑保持原有数据流。只替换容器和呈现层：设备卡片、状态徽标、操作按钮、二维码说明、错误提示和空状态都使用同一套表面与间距规则。长文本和小屏布局继续使用原有滚动/堆叠策略。

## 交互、错误与无障碍

- 主操作在每个状态只有一个明确视觉优先级；危险或不可用动作不会只靠颜色区分。
- 安装文件替换期间，关闭按钮和取消按钮保持禁用；完成或失败后恢复可关闭/重试状态。
- 长更新说明支持键盘 Home/End、滚动条或等价的触摸滚动；进度控件报告可访问名称、当前值和阶段。
- Android 触摸目标保持足够尺寸，字体放大时按钮堆叠而不是裁切；系统返回不会绕过更新保护。
- 主题切换不重建正在进行的窗口或丢失进度状态。

## 实施阶段

1. **基础 token 与品牌资产**：确定两端颜色、圆角、边框、辉光、按钮、状态色和图标几何；生成 Windows 多尺寸图标与 Android 自适应资源。
2. **Windows 更新体验**：统一确认、进度、失败、完成和短通知，并保留现有更新回归覆盖。
3. **Windows 主界面与配对**：替换设备卡片、主操作、二维码和配对提示的表面与图标；不触碰设备/传输业务逻辑。
4. **Android 主界面与弹窗**：统一 BridgeUi、BridgeDialogs、设备/传输/配对/更新页面，并接入新的自适应图标。
5. **跨端回归与视觉检查**：浅色/深色、窄窗口/大字体、DPI/屏幕密度、长文、失败和安装保护；确认图标在 Windows、Android 启动器和小尺寸下仍清晰。

每个阶段完成后先构建和运行针对性 smoke test，再进入下一阶段；不把发布和版本文件带入视觉改造提交。

## 验收标准

- 更新流程所有阶段均使用清透浅色玻璃组件，截图中没有回退到旧的系统标题栏、原生文本框或默认按钮样式。
- Windows 与 Android 的主页面和主要弹窗具有一致的色彩层级、圆角、状态语义和品牌图标；Android 图标不再使用与电脑不同的旧箭头图标。
- 品牌图标在 Windows `.ico` 多尺寸、Android 自适应遮罩和小尺寸显示下都能识别文件夹与双向传输箭头。
- 浅色与深色主题、键盘/触摸操作、辅助功能、长文本、失败重试、取消和安装防误关均通过现有及新增测试。
- `dotnet build`、两个 smoke test 项目构建、Android 单元/UI 相关测试和现有发布离线校验按仓库约定执行；不执行正式发布。
