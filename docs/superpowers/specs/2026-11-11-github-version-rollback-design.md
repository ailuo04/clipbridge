# ClipBridge Windows 更新入口与历史版本回退设计

状态：设计稿，尚未实施；实现前须经用户审阅。
日期：2026-11-11

## 目标与范围

在 Windows 主窗口中理顺“设置”“接收文件夹”和更新入口；将更新状态放在接收文件夹上方；在设置页提供备用检查入口和历史版本回退入口。用户可以查看 GitHub 已发布版本并主动选择旧版本回退。

本设计不改变 Android 更新体验、正式发布流程、发布密钥或签名协议；不执行发布，也不改变普通自动更新行为。所有回退候选必须来源于 GitHub Release 标签，并且通过该版本的签名清单与包完整性校验。

## 界面与交互

### 侧栏

- 侧栏底部自上而下排列更新状态控件、“接收文件夹”和“设置”；更新与日常导航之间用留白/分隔建立层级，设置与文件夹入口也应有清晰区分。
- 空闲时以椭圆形控件显示“当前为最新版”；点击开始手动检查。检查中显示不可重复触发的检查状态。
- 如果检查到新版，显示版本号和“立即更新”主操作；点击后沿用现有更新确认及安装流程。
- 检查失败显示可辨识的失败状态和重试入口，不能误显示为“当前为最新版”。检查成功且无新版时恢复最新版状态。

### 设置页

- 主题选项下方先放备用“检查更新”按钮，再提供“回退到历史版本”入口。点击回退入口后展示 GitHub 已发布版本列表及其加载状态。
- 列表展示版本号、发布日期和预发布标记；默认按版本从新到旧排序。只允许选择低于当前运行版本的版本，避免把“回退”误作重装当前版本或升级。
- 选中版本后显示目标版本和确认提示。用户明确确认后才开始下载、验证、关闭当前程序并替换文件。
- 网络错误、GitHub 限流、无可用历史版本、无有效签名清单等情况均显示明确原因和可用的返回/重试操作，不静默改变安装。

## GitHub 版本发现与验证

1. 从 `ailuo04/clipbridge` 的 GitHub Releases 列表读取已发布条目，按分页遍历；排除草稿，保留并明确标注预发布版本。GitHub 返回的标签仅作为候选版本标识，不作为可信更新元数据。
2. 对每个低于当前版本的候选标签，从固定的 GitHub Raw 仓库地址读取对应的 `manifest-<version>.json`。缺失、超限、格式不合法或签名无效的候选不可选。
3. 用应用内当前/轮换公钥验证 RSA-SHA256 签名；解析签名载荷，并要求清单内 Windows 版本与 Release 标签版本严格一致。
4. 校验安装包 URL 为 HTTPS，且主机、仓库和路径精确匹配 `ailuo04/clipbridge` 的 `ClipBridge-<version>-win-x64.zip`；拒绝其它主机、仓库、路径或版本不匹配的地址。回退只用经验证的 Windows ZIP，不采用 Release API 返回的任意下载 URL 或安装器链接。验证 ZIP 大小在现有允许范围内，SHA-256 格式正确。
5. 安装前沿用现有下载器逐字节限制长度并校验 SHA-256，再安全解压。未通过任何一步时，不启动安装辅助进程，也不触碰安装目录。
6. Releases API 的网络失败或匿名速率限制按加载失败处理，保留设置页并允许重试；不得以未经验证的标签或缓存数据继续安装。

版本发现和历史清单读取可在一次列表加载任务内异步完成；界面显示加载进度或状态并允许取消/返回。按 GitHub API 分页直到读取完整列表或用户取消，每次请求设置明确超时，并限制 API/清单响应体大小；不得设置会让较旧发布版本悄然无法发现的固定页数上限。版本发现使用固定的官方仓库地址，不使用可变环境变量替换来源。

## 更新协议与安装流程边界

- 将“签名清单验证”和“是否允许此版本”的判断分开：普通自动更新仍仅接受高于当前版本的目标；用户主动回退的入口可接受低于当前版本、且其余验证全部通过的目标。
- 回退不能借用或修改最新版 `latest-v2.json` 来伪装降级；只能消费固定官方仓库中名称与所选版本对应的签名版本清单。
- 将已验证的目标转换为现有更新安装流程接受的版本、URL、大小、哈希和说明数据。更新弹窗需明确标注“回退到 vX.Y.Z”，不能沿用“发现新版”的措辞。
- 沿用现有暂存、ZIP 路径安全检查、独立更新助手、等待主程序退出、启动确认及失败恢复机制。回退失败时恢复原安装版本并重新启动；只有目标版本启动确认成功后才算完成。
- 下载前如存在活动文件发送或传输，继续沿用现有阻止安装的行为，并提示用户先完成传输。

## 主要组件职责

- `WorkspaceForm`：侧栏最新版状态控件、设置备用检查按钮、历史版本列表/选择页和回退确认入口；控件随主题正确更新。
- `TrayAppContext`：协调检查状态、版本发现、用户发起的回退下载与现有安装助手；防止检查和安装任务重入。
- `UpdateProtocol`：提供安全的 Release 列表读取、签名清单验证及目标版本校验；保持自动更新与用户主动回退两种版本策略分离。
- `AvailableUpdate` 或等价内部模型：携带已验证的目标信息及更新/回退意图，使提示文案与安装流程能准确表达操作类型。
- `SelfUpdate`：继续负责经过哈希校验的 ZIP 暂存和可恢复替换，不负责发现版本或降低签名门槛。

实现时应优先沿用现有 UI 和更新模式，避免无关重构；确需拆分责任时只新增完成上述流程所需的最小内部组件。

## 失败与安全处理

- 草稿 Release 不进入列表；预发布版本显式标记，符合签名条件的已发布预发布版本仍可由用户主动选择。仅提供符合仓库版本号格式且存在有效 Windows 签名 ZIP 清单的条目；不满足条件的发布必须明确标示不可回退，不可降低校验标准。
- Release 标签缺失、版本格式异常、标签与签名载荷不一致、清单不可读/不可验证、URL 越界、包尺寸不符、SHA-256 不符或 ZIP 内容不安全：拒绝该候选或此次安装，并给出可理解的原因。
- GitHub API 限流或网络中断：停止加载并允许稍后重试；不将 API 返回的数据当作已验证清单。
- 安装失败或新进程未能正常启动：保留当前已有恢复行为，恢复原文件并尝试重新打开原版本；不得报告回退完成。
- 不记录令牌、密钥或任何私钥材料；运行时不要求发布凭据。

## 验收与验证

- UI smoke：检查侧栏控件位置、最新版/检查中/有更新/失败状态、按钮启用状态、主题切换、设置备用入口、历史版本列表与确认操作。
- 更新协议测试：分页及草稿排除；版本排序和低于当前版本的筛选；签名成功/失败；标签与清单版本不匹配；不受信任主机/路径；超大清单；API 错误或限流；无效或缺失历史清单。
- 更新体验测试：回退下载仍验证内容长度和 SHA-256；取消和下载失败不留下部分包；安装助手成功启动目标版本；启动失败恢复原版本；自动更新继续拒绝相同或更低版本。
- 执行 Windows 主项目构建及更新/UI smoke tests。若实现触及更新协议或发布脚本，按项目发布约定补跑其要求的构建与测试；本设计本身不修改发布脚本。
- 真实 GitHub 网络、真实安装目录原位回退和安装器权限行为需单独注明是否验证；合成 smoke test 不得声称覆盖真实安装。

## 明确不做

- 不关闭或绕过 RSA 签名、HTTPS、大小或 SHA-256 校验。
- 不把 GitHub Release 列表或任意 Release 下载链接当成可信安装清单。
- 不允许后台定时检查自动降级。
- 不恢复 Gitee 作为新发布或回退渠道。
- 不在本设计阶段修改代码、推送版本或发布 GitHub Release。
