# ClipBridge 安卓与 Windows 手动互传设计

日期：2026-11-02（Asia/Shanghai）
状态：已获用户确认，待进入实施计划。
代码位置：`D:\互传\github-public`

## 目标

ClipBridge 支持一加 15 手机与 Windows 电脑之间的局域网双向数据互传，包含：

- 手机与 Windows 双向发送纯文本剪贴板内容。
- 手机与 Windows 双向发送文件。
- 文字和文件都由用户在 ClipBridge 界面中主动点击发送。
- Windows 不再自动监听或自动转发系统剪贴板。
- 不使用 Shizuku、ADB 或默认输入法。
- 同一局域网内支持自动发现；发现失败时支持手动输入局域网 IPv4 地址。
- 使用现有配对密钥和加密通信，不把剪贴板正文或配对密钥写入日志。

“主动发送”表示用户打开对应端的 ClipBridge，确认当前内容或文件后点击发送。接收端写入剪贴板或保存文件后不得再次自动发送，防止循环和意外传播。

首版只覆盖同一 Wi-Fi 或手机热点下的局域网通信。跨互联网中继、文件夹递归、通讯录、短信、相册整库同步和断点续传不属于本次范围。

## 当前项目背景

- Windows 工程使用 .NET 10 Windows Forms，当前正式代码版本为 0.3.10。
- 现有 `WindowsClipboardListener` 监听 Windows 文字剪贴板变化；本设计要求停止使用它的自动发送路径，并移除或关闭相关 UI 和状态文案。
- 现有 `SyncNode` 已实现 UDP 45821 设备发现、TCP 45822 文字通信、配对密钥派生、AES-GCM 加密、消息去重和远端文字写入。
- 当前代码库没有安卓工程、APK 或文件传输业务。
- Windows 端配对密钥、签名更新协议、安装目录权限策略和 GitHub 发布约定不属于本次功能改动范围。
- 本次设计和后续本地实现不会自动发布安装包或修改 GitHub Release。

## 用户流程

### 手机发送剪贴板

1. 用户打开手机端 ClipBridge。
2. 在设备列表中选择已配对的 Windows 设备。
3. 点击“发送剪贴板”。
4. 应用读取当前剪贴板中的纯文本，并显示可滚动预览、字节数和目标设备。
5. 用户确认发送。
6. 发送成功后显示结果；失败时显示可读的原因并提供重试。

如果剪贴板为空或内容不是首版支持的纯文本，应用显示明确提示，不创建空消息。剪贴板正文只在用户点击发送后的当前前台操作中读取，不建立后台监听。

### Windows 发送剪贴板

1. 用户在 Windows 中复制文字。
2. 用户打开 ClipBridge 控制面板或托盘菜单。
3. 用户点击“发送当前剪贴板”。
4. ClipBridge 读取当前 Windows 纯文本剪贴板，显示目标设备和发送结果。
5. 手机收到后写入系统剪贴板；接收操作不触发再次发送。

Windows 端不再因为用户在其他应用中复制文字而自动联网，也不再显示“同步中”或“等待新复制内容”等自动同步状态。

### 文件发送

1. 发送方在 ClipBridge 中选择文件、拖入文件，或从手机系统分享菜单选择 ClipBridge。
2. 发送方选择目标设备，查看文件名、数量和总大小。
3. 接收方收到确认请求，查看来源设备、文件名、数量和总大小。
4. 接收方接受后开始传输；拒绝或取消时双方显示对应结果。
5. 接收端写入临时文件，传输完成后校验大小和 SHA-256，校验通过后再移动为最终文件。
6. 同名文件不覆盖已有文件，自动生成安全的新文件名，并提供打开文件或所在目录的入口。

默认保存位置：Windows 为用户可写的 ClipBridge 接收目录；安卓为应用可访问的 Downloads/ClipBridge 目录。安卓使用系统文件选择器和分享接口，不申请整个外部存储空间的管理权限。

## 推荐架构

### 安卓客户端

新增原生 Kotlin 安卓工程，负责：

- 设备发现、手动地址、配对密钥导入和撤销。
- 手动读取前台剪贴板并发送纯文本。
- 接收 Windows 文本并写入系统剪贴板。
- 通过系统文件选择器或分享接口选择待发送文件。
- 接收文件并保存到用户可访问的位置。
- 展示设备、连接、发送、接收和错误状态。
- 保存配对材料时使用 Android Keystore 保护本机敏感数据。

安卓应用不实现后台剪贴板轮询、Shizuku 服务、ADB 服务或默认输入法服务。文件传输和手动文字发送都由应用界面触发；接收连接可以在应用运行期间处理，必要的前台运行状态必须有明确通知和停止入口。

### Windows 客户端

继续使用现有 Windows Forms 工程，并按职责拆分新增能力：

- `SyncNode` 保留设备发现、配对密钥和加密文字通道，增加显式发送文字的方法。
- 移除或停用 `WindowsClipboardListener` 到 `SyncNode.OnLocalClipboardTextChanged` 的自动发送链路。
- 控制面板和托盘菜单增加“发送当前剪贴板”，并删除自动同步开关、自动同步确认提示和相关状态文案。
- 新增文件选择、拖拽、接收确认和传输进度组件，避免把文件队列与所有 UI 状态塞进 `ControlPanelForm`。
- 将文本发送、文件发送和设备状态使用清晰的服务边界连接，使后续增加图片或其他内容类型时不需要重写设备连接层。

## 协议设计

### 文字通道

保留现有 ClipBridge v1 文字协议以减少 Windows 端兼容风险：

- UDP 45821 用于局域网广播和设备发现。
- TCP 45822 用于文字控制帧。
- 现有 `ClipboardMessage` 的 `Type`、`MessageId`、`OriginDeviceId`、`Text`、`TimestampUtc` 字段继续使用。
- 文字内容只在用户点击“发送当前剪贴板”并确认后创建消息。
- 保持 256 KiB UTF-8 文本上限、消息时效校验和消息 ID 去重。
- 使用现有配对密钥派生的 AES-GCM 密钥，每个消息使用随机 nonce 和认证标签。
- 接收端验证来源、时间戳、长度、消息 ID 和认证标签后才写入本地剪贴板。
- 接收端写入剪贴板时标记为远端应用内容，禁止再次进入手动发送队列；用户需要再次点击发送才会传播。
- 不把清空本地剪贴板作为远端清空指令。
- 断网时不自动补发用户之前复制过的文字；只有用户再次点击发送才创建新的消息。

现有 Windows v1 文字协议没有可靠的“对端已写入剪贴板”确认语义。本次 UI 的“发送成功”应表示协议消息通过并收到明确应用层确认；若实现阶段暂时无法加入确认帧，文案必须显示为“已发送”而不是“对方已写入”。

### 文件通道

文件使用独立的 TCP 45823 通道，避免改变现有 45822 文字帧的语义：

1. 发送方发送经过认证加密的传输请求，包含传输 ID、来源设备、文件名、文件大小、文件数量、分块大小和每个文件的 SHA-256。
2. 接收方明确接受或拒绝；未接受前不发送文件内容。
3. 发送方按固定大小分块流式写入，接收方按传输 ID 和序号写入临时文件。
4. 每个控制帧验证类型、传输 ID、长度、顺序、总量和时间戳。
5. 接收总字节数不能超过已确认的元数据大小；文件名只允许安全的文件名部分，拒绝路径分隔符、目录穿越和非法目标路径。
6. 完成后校验文件长度和 SHA-256，成功后原子移动为最终文件；失败、取消或断网时删除未完成临时文件。
7. 同名文件使用安全重命名策略，不覆盖接收目录已有文件。
8. 文件传输与文字发送共享设备列表和连接状态，但拥有独立的队列、取消令牌和错误状态。
9. 文件内容、文件名和传输控制信息都必须通过配对连接认证；不开放无配对 HTTP 下载地址。

文件通道的实现可以复用现有 `SharedProtocol` 的 AES-GCM、长度前缀和配对密钥基础代码，但应使用独立的协议域派生文件密钥，避免把文字和文件业务混为一个消息类型。

## 状态与错误处理

| 场景 | 预期行为 |
| --- | --- |
| 未配对 | 引导用户输入 Windows 显示的配对密钥或完成配对流程 |
| 自动发现失败 | 显示发现失败原因，允许输入局域网 IPv4 地址 |
| 设备离线 | 禁止提交发送或提示连接正在建立，避免假装已发送 |
| 剪贴板为空 | 显示空剪贴板提示，不发送空消息 |
| 文本超过限制 | 显示大小限制，不发送 |
| 接收方拒绝 | 发送方显示已拒绝，接收方不创建文件 |
| 用户取消 | 两端显示已取消，清理临时文件 |
| 网络中断 | 显示传输失败，删除未完成文件，允许用户手动重试 |
| 密钥错误或认证失败 | 丢弃消息或文件，显示配对失败，不写入剪贴板或最终目录 |
| 文件哈希不匹配 | 删除临时文件，显示完整性校验失败 |
| 磁盘空间不足 | 停止传输并清理临时文件，保留已有文件 |
| Windows 剪贴板被占用 | 延迟重试当前读取，仍失败时显示用户可重试的提示 |
| 安卓系统不允许当前剪贴板操作 | 显示读取或写入失败，不伪造发送成功 |

应用日志只记录设备、传输 ID、状态、大小和错误类型，不记录文字正文、文件内容、配对密钥或完整路径中的敏感部分。

## UI 范围

### Windows

- 设备卡片显示设备名称、地址、在线状态和可用功能。
- 控制面板提供“发送剪贴板”“发送文件”两个主要入口。
- 托盘菜单提供同样的两个发送入口和接收状态。
- 发送剪贴板前显示文本预览和目标设备。
- 文件传输使用队列列表显示等待确认、传输中、完成、取消和失败。
- 删除“开启剪贴板同步”“暂停剪贴板同步”及其自动监听说明。

### 安卓

- 主界面显示已配对设备和连接状态。
- 提供“发送剪贴板”“选择文件发送”两个主要入口。
- 文本发送页支持预览、目标选择、确认和结果反馈。
- 文件页使用系统文件选择器和系统分享入口。
- 接收请求显示来源、文件名、数量和大小，并提供接受、拒绝、取消。
- 设置页提供配对密钥、手动地址、接收目录和撤销配对。

首版不做剪贴板历史列表、云同步、自动识别敏感文本和内容分类。用户可以在发送前查看预览并自行决定是否发送。

## 验证计划

### 协议和单元测试

- C# 与 Kotlin 对同一固定输入产生一致的密钥派生结果。
- AES-GCM 固定测试向量覆盖中文、表情、空内容、最大合法文本、错误密钥和篡改密文。
- 覆盖非法帧长度、过期消息、重复消息、错误来源和超限文本。
- 文件分块重组后的大小和 SHA-256 与发送端一致。
- 文件名清理拒绝路径穿越和非法目标路径。
- 取消、断网、接收拒绝和校验失败都会清理临时文件。

### Windows 验证

- 构建 Windows 主工程。
- 运行现有 UI smoke test。
- 验证 Windows 复制文字后不会自动联网或自动发送。
- 验证点击“发送当前剪贴板”才会生成文字消息。
- 验证接收手机文字后写入 Windows 剪贴板且不会自动回传。
- 验证文件选择、拖拽、接收确认、进度、取消、同名重命名和校验失败。
- 保持更新协议和发布相关测试通过。

### 一加 15 真机验证

- 手机打开 ClipBridge 后发送中文、英文、链接、表情和长文本到 Windows。
- Windows 主动发送文字后，手机切换到微信或浏览器进行粘贴。
- 手机发送小文件、中文文件名、多文件和至少 1 GiB 视频到 Windows。
- Windows 发送上述文件类型到手机并确认保存位置和哈希。
- 验证同一 Wi-Fi、手机热点、切换网络、临时断网和重新连接。
- 验证拒绝、取消、重复文件、磁盘空间不足和错误配对密钥。
- 确认手机和 Windows 都不会在用户未点击发送时传播剪贴板内容。

真机测试完成前，只能声称代码构建和自动化测试通过，不能声称一加 15 上的完整业务已经验证。

## 游戏期间不打扰（实施中补充的用户硬性要求）

用户在游戏时不能因开发操作或 ClipBridge 接收/更新而被切换出游戏。开发期间仅运行无界面测试，不启动应用、UI smoke test、安装器或模拟器，不自动打开预览。软件默认从托盘安静运行；文件请求进入待接收列表，只有用户点击后显示确认。自动更新检查只记录可用更新，不显示对话框。收到剪贴板文字不弹窗、不抢焦点，不触发窗口闪烁或系统提示音。交互式 UI 验证留待用户不玩游戏时进行，当前只编译该测试项目。
