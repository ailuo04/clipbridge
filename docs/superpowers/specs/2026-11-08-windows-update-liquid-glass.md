# 2026-11-08 Windows 更新弹窗液态玻璃改版

## 目标

把电脑端更新窗口从独立的浅色长卡片，改成 ClipBridge 软件正中央的模态玻璃卡片，背后保留并雾化控制面板。解决原窗口偏白、层级过多、进度动画卡顿的问题。

参考 gpt++ 的更新弹窗：窄卡、少量文字、状态先行、单一主要动作。ClipBridge 保留自己的品牌色与更新安全说明。

## 交互与布局

- 更新确认、下载、校验、安装等待、完成、失败与短通知共用同一个弹窗组件。
- 弹窗覆盖整个 ClipBridge 客户区，玻璃卡始终水平、垂直居中；软件窗口移动或缩放时同步跟随。
- 背景取当前控制面板，缩放到低分辨率后做两段重采样并轻微加雾，保留面板分区和明暗层次；不把背景抹成纯色，也不逐帧做实时模糊。
- 主卡宽度 432 逻辑像素，更新态高度 472；短通知使用 338 的紧凑高度。小窗口按比例缩放，最小不低于 0.65。
- 更新说明直接排在玻璃卡上，只用一个半透明阅读内嵌层，不再堆叠状态胶囊、说明卡和进度卡。

## 性能

- 背景只在显示、尺寸或主题变化时重新生成一次，并以小图缓存。
- 卡片静态玻璃、边框、内嵌阅读层与进度槽在状态变化时烘焙到一张位图；常规重绘直接贴图。
- 进度只重绘进度区域，动画 33 ms 一帧，数值动画结束后自动停止计时器。
- 替换旧帧位图时延迟回收，避免正在绘制时释放 GDI+ 对象导致 `Parameter is not valid`。

## 其他窗口防闪白

- 主控制面板、设备与配对窗口和文件请求窗口启用整窗合成缓冲（WS_EX_COMPOSITED + 双缓冲），缩放时子控件不再分别擦除，边框不再露出白色残影。
- 设备窗口缩放只重排内容，不再冻结整个窗口；二维码面板同步双缓冲。
- 这些路径仍以普通 GDI 绘制为主，动画保持按需重绘，适配 120Hz 刷新率。

## 安全与行为不变

- RSA 签名清单、安装包 SHA-256、大小和 HTTPS 校验保持原样。
- 下载可取消；替换文件阶段禁止关闭；完成后才显示 100%；失败显示真实原因并可重试。
- 独立安装助手使用同一玻璃卡，但不依赖主程序作为 Owner；失败时引导重新打开应用，不提供不可用的重试。
- 启动失败、已是最新版本和检查失败继续使用同一组件的紧凑通知样式。

## 可访问性

- 弹窗和卡片向辅助技术提供版本、大小、阶段、百分比和错误原因。
- 支持 Tab 在动作间切换、Esc 关闭（下载中触发取消）、方向键/Page/Home/End 滚动长更新说明。
- 高对比度或系统关闭动画时直接更新数值，不保留循环动画。

## 验证

- `tools/UiSmokeTests` 的 `--updates-only --capture`：覆盖居中、模糊背景层次、缓存复用、进度重绘范围、浅深色、1.5 倍缩放、长说明滚动、取消/安装保护、完成/失败和紧凑通知。
- 主项目 Release 构建、UI/更新两个 smoke 项目构建。
- 真实安装升级、真实 GitHub 下载与正式发布未在本地执行；发布仍需按仓库约定走 GitHub Actions。
